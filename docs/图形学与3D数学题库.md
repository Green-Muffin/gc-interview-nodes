## 一、向量、旋转与变换

### 1. 点积、叉积与归一化分别有什么几何意义？

**答案：**

点积 `a·b = |a||b|cosθ`，可用于投影和夹角判断。只有控制了长度，尤其归一化后，才能直接用点积比较方向相似程度。

三维叉积产生垂直于两向量的向量，长度为 `|a||b|sinθ`，方向与采用的坐标约定有关；二维可定义标量叉积 `cross(a,b)=ax*by−ay*bx` 判断有向面积和转向。

归一化得到单位方向，零向量没有唯一方向，应先处理接近零的长度。做平方距离比较时通常不需要开方。

### 2. 如何判断目标在人物左边还是右边？

**答案：**

直接用角色的局部右方向做点积通常更清楚：`side = dot(right, targetPosition - position)`，大于正容差在右边，小于负容差在左边，中间视为近共面或正前／后。

如果只考虑水平面，先按约定投影到该平面；角色可能倾斜时，应明确使用世界 up 还是角色 up。使用叉积也可以，但取哪一分量和符号依赖轴约定，不能脱离坐标定义死背 `.y > 0`。

前后可用 forward 点积判断；左右为零不代表目标一定在正前方。

### 3. 四元数为什么适合表示旋转？仍有哪些坑？

**答案：**

单位四元数紧凑地表示三维旋转，适合复合与插值，可避免以欧拉角参数化连续旋转时的万向锁问题。`q` 与 `−q` 表示同一个空间旋转。

乘法顺序不交换，应明确局部／世界复合顺序。不要直接对四个分量随意加减后当作合法旋转，必要时归一化；插值需处理符号和路径选择。

欧拉角便于某些编辑操作，但同一旋转可有多组角度；使用四元数也不自动解决摄像机控制逻辑或插值速度设计。

### 4. 矩阵乘法为何能组合变换？应注意什么？

**答案：**

矩阵把变换表达为线性代数运算；齐次坐标允许在 4×4 矩阵中统一表示三维平移与仿射变换。普通三维线性变换本身不能直接表示平移。

采用列向量约定时，`p' = M2 * M1 * p` 表示先做 M1 再做 M2；行向量约定相反，不能混用公式。矩阵乘法一般不可交换，旋转后平移与平移后旋转结果不同。

位置常用 w=1，方向常用 w=0。非均匀缩放时法线不能直接照搬位置变换，常需用线性变换的逆转置并归一化。连续累积变换也要考虑浮点误差。

## 二、空间相交判断

### 5. 直线、射线与线段有什么区别？为何“端点在两侧”不足以判断射线相交？

**答案：**

可统一写成 `P(t)=O+tD`：直线允许任意实数 t；射线要求 t≥0；长度参数化的线段则限制在约定区间。

线段端点位于某条直线两侧，最多说明它可能与该无限直线相交。交点可能在射线原点背后，或不在目标有限线段内，还需检查参数范围。

例如射线从原点向右，目标竖线段位于 x=−1：两端虽可分居 x 轴两侧，交点却在射线背后。平行、共线、零长度与端点接触也需明确。

### 6. 二维射线与线段如何求交？

**答案：**

射线为 `O+tD`，线段为 `A+uE`，其中 `E=B−A`、t≥0、0≤u≤1。定义二维叉积 `cross(a,b)=ax*by−ay*bx`。

当 `den=cross(D,E)` 非零时：

```text
t = cross(A-O, E) / den
u = cross(A-O, D) / den
相交条件：t >= 0 且 0 <= u <= 1
```

den 接近零时先区分平行与共线；共线时将端点投影到非零射线方向上，检查是否与 t≥0 区间重叠。零方向和零长度线段应单独处理。浮点容差要匹配数据尺度，并明确是否把端点接触算相交。

### 7. 射线与 AABB 如何用 Slab 方法求交？

**答案：**

AABB 是各轴区间 `[min_i,max_i]` 的交集。逐轴求射线处于每个区间内的 t 范围，再取交集。

```text
tEnter = 0, tExit = +∞          # 有限射线可用最大距离替代 +∞
对每个轴 i：
    若 D[i] = 0：
        O[i] 不在 [min[i],max[i]] 内则不相交，否则跳过该轴
    否则：
        t1 = (min[i] - O[i]) / D[i]
        t2 = (max[i] - O[i]) / D[i]
        若 t1 > t2，交换二者
        tEnter = max(tEnter, t1)
        tExit  = min(tExit, t2)
        若 tEnter > tExit，不相交
所有轴通过则相交
```

起点在盒内时 tEnter 可为 0。若 D 非单位向量，t 不直接等于世界距离。二维轴对齐矩形是同一方法的两轴版本；任意旋转矩形可先转换到它的局部空间，再检测局部盒，并注意参数化一致性。

参考：[PBRT：包围盒求交](https://www.pbr-book.org/4ed/Shapes/Basic_Shape_Interface)。

## 三、渲染流水线与透明

### 8. GPU 光栅化流水线包含哪些阶段？

**答案：**

常见流程为：应用侧准备数据与渲染状态 → 输入装配与顶点处理 → 可选细分／几何等阶段 → 裁剪与视口映射 → 光栅化 → 片段着色 → 深度、模板、混合与输出。

具体硬件和 API 可能重排部分工作，例如提前深度测试；现代 GPU 也有 Compute、Mesh Shader 等不同工作路径。不是每帧都把所有资源重新从磁盘上传，也不能假定所有设备都有独立显存。

Unity 的 BIRP／URP／HDRP 是组织渲染流程的引擎层方案，与 GPU 单次绘制的阶段不是同一个层级。

参考：[Direct3D 图形流水线](https://learn.microsoft.com/en-us/windows/win32/direct3d11/overviews-direct3d-11-graphics-pipeline)。

### 9. 模型、世界、观察、裁剪、NDC 与屏幕空间如何转换？

**答案：**

以列向量约定为例：`clip = P * V * M * position`。M 将模型坐标变到世界，V 变到相机观察空间，P 生成齐次裁剪坐标；通过裁剪后做透视除法，得到 NDC，再经视口变换得到屏幕位置。

齐次裁剪空间不是投影之后再凭空添加的一套步骤；除以 w 的顺序有意义。深度范围、屏幕 Y 方向等受图形 API、渲染目标和引擎约定影响，不能把某套 OpenGL／DirectX 口诀当作所有平台的固定值。

### 10. 顶点着色器、片段着色器与像素有什么区别？Forward／Deferred 又是什么？

**答案：**

典型光栅化流程包括顶点处理、图元装配与裁剪、光栅化、片段处理及深度／模板／混合等阶段；硬件可能根据条件提前执行部分测试。

- **顶点着色器**：变换顶点位置，计算并输出供插值的数据。
- **片段着色器**：对光栅化后的候选片段计算颜色等输出，常涉及纹理采样和光照。
- **Forward**：绘制对象时计算相应光照；透明、MSAA 和带宽预算等因素会影响选择。
- **Deferred**：先写入 G-buffer，再集中处理光照；适合一定条件下的多光源，但增加带宽和中间缓冲，透明通常另走路径。

渲染路径由相机／Renderer／管线配置和 Shader 支持共同决定，不是 Standard Shader 独立“选择一条流水线”。URP 的 Forward、Forward+、Deferred 等可用性需结合包版本。

片段是图元覆盖某个采样位置产生的候选数据，不保证最后写成一个可见像素。同一像素可能被多个图元覆盖，片段还可能被丢弃或测试淘汰；MSAA 等情况下还需区分像素与采样。

### 11. Alpha Blend 的公式是什么？为什么透明物体难排序？

**答案：**

对常见直通 alpha 颜色，`Blend SrcAlpha OneMinusSrcAlpha` 的 RGB 结果为：

`Cout = Csrc * Asrc + Cdst * (1 - Asrc)`

这是给定混合因子的结果，alpha 通道如何写入还要看是否配置独立因子。预乘 alpha 的源颜色已经乘过 alpha，常用 `One, OneMinusSrcAlpha`，不能再混用同一套因子。

透明混合一般不交换，所以常按远到近绘制并谨慎处理深度写入。相交几何、粒子与跨对象排序可能无法仅靠对象级排序完全解决；最终效果还取决于线性／伽马空间和目标格式。

### 12. Alpha Test／Clip 与 Alpha Blend 有什么区别？

**答案：**

Alpha Clip 按阈值丢弃片段，常用于树叶、栅栏等镂空形状；Alpha Blend 将源与已有颜色混合，适合玻璃、烟雾等半透明。

Clip 的边界通常是保留或丢弃，可结合抗锯齿策略改善锯齿；Blend 支持部分透光但带来排序与 Overdraw。被丢弃不意味着完全没有 GPU 成本，alpha 裁剪也可能影响早期深度优化。现代实现常在 Shader 中使用 `clip`／discard，而不是只背旧 ShaderLab AlphaTest 指令。

### 13. 相机 Near／Far Clip Planes 如何影响可见性和深度精度？

**答案：**

近远裁剪面限定视锥的深度范围，不等于沿每个像素射线统一截取同一欧氏距离。物体越过裁剪面可能被裁剪，并非只有对象中心超界才消失。

传统透视深度映射中 Near 太小、范围过大可能加重 Z-fighting；提高合适的 Near、缩小不必要范围可改善。反向 Z 与浮点深度改变精度分布，因此要结合 API 与管线，不能只凭 Far 数字判断。

多相机、天空和大型世界还需明确各自深度与裁剪策略。

## 四、光照、纹理与细节

### 14. Lambert 漫反射公式如何解释？

**答案：**

常见简化写法为 `diffuse = Kd * lightColor * max(dot(N,L),0)`，N 与指向光源的 L 应归一化，并位于同一坐标空间。

点积表达余弦衰减，负值截为零避免背面受该正面光贡献。若从严格的 Lambert BRDF 出发，还涉及 `albedo/π` 等归一化与辐射度量约定；距离衰减、阴影和入射光强不能由这个简式全部代表。

### 15. Shadow Map 与 Shadow Volume 有什么区别？本影／半影是两种算法吗？

**答案：**

Shadow Map 从光源渲染深度，再在接收表面比较深度；受分辨率、偏移和过滤影响，适合常见实时管线。Shadow Volume 从遮挡几何构造阴影体，配合模板等方式判断视点／片段是否在阴影区域，成本与几何和覆盖有关。

本影与半影描述光源被完全或部分遮挡的区域，不是两种阴影算法。面光源、遮挡物与接收面的几何关系决定软阴影；简单模糊 Shadow Map 只是近似，不能和真实可见度积分等同。

### 16. MipMap 有什么作用？大约增加多少空间？

**答案：**

Mip 链为纹理准备逐级缩小的版本，在远距离或纹理缩小时选择合适层级，降低高频闪烁并改善采样局部性；它不是万能的几何抗锯齿方案。

理想二维完整链的像素总量约为 `1+1/4+1/16+...=4/3`，即较基准层约多三分之一；实际大小还受尺寸、压缩块和层数影响。斜视表面可结合各向异性过滤，UI 等特定场景需根据缩放和内存需求决定是否启用。

### 17. LOD 的收益和代价是什么？

**答案：**

LOD 根据屏幕覆盖、距离或重要性切换几何、材质、动画等细节，目标是在可接受画质下减少不必要工作。

代价包括额外制作与存储、切换痕迹、过渡期间双份绘制或其他开销；采用流式加载时也不必始终让所有 LOD 同时常驻。减面只影响部分工作，若瓶颈是透明填充、阴影或带宽，LOD 策略也需对应这些成本。

### 18. 水面倒影如何实现？扰动纹理等于生成反射吗？

**答案：**

常见反射来源包括平面反射相机、反射探针／Cubemap、屏幕空间反射（SSR）或光线追踪。法线／UV 扰动改变采样和表面方向，模拟水波，但本身不生成真实场景倒影。

平面反射需处理镜像相机、裁剪平面和额外绘制；Cubemap 成本较可控但局部视差有限；SSR 缺少屏幕外与被遮挡的信息。水面还可能混合 Fresnel、折射、深度着色与泡沫，按目标画质和平台预算选择。
