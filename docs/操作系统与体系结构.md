## 一、虚拟内存与地址转换

### 1. 虚拟内存有什么作用？

**答案：**

每个进程看到独立、连续的虚拟地址空间，操作系统和硬件把虚拟页映射到物理页。它提供进程隔离、按页保护、共享内存、文件映射和按需分配，也让程序不必依赖物理内存的连续布局。

访问尚未建立有效映射的页会触发缺页异常，操作系统分配／调入页面并更新页表；若内存压力大，频繁换页会产生严重抖动。虚拟地址空间很大不代表实际物理内存无限。

### 2. 虚拟地址如何通过页表转换成物理地址？

**答案：**

虚拟地址拆为虚拟页号和页内偏移。MMU 用虚拟页号查询多级页表，页表项给出物理页框、权限和状态，再与页内偏移组合为物理地址。

多级页表只为实际使用的地址范围分配下级表，减少稀疏地址空间的页表内存。大页减少页表层级和 TLB 压力，但增加内部碎片，也让分配迁移更困难。

### 3. TLB 是什么？为什么查询很快？满了怎么办？

**答案：**

TLB 是 CPU/MMU 内部的地址转换缓存，保存最近使用的虚拟页到物理页映射，通常采用组相联等硬件结构并行比较标签，因此远快于逐级读取内存页表。

TLB 未命中时由硬件页表遍历器或系统软件查页表并回填；容量满时按硬件替换策略淘汰旧项。进程切换可刷新部分条目，或用 ASID／PCID 区分地址空间。TLB 本身不是放在普通内存里逐项线性查询的表。

### 4. 32 位和 64 位系统／程序有什么区别？

**答案：**

核心区别是通用寄存器和地址计算宽度、指针／size_t 等 ABI 类型大小，以及可直接表示的虚拟地址范围。常见 32 位对象指针为 4 字节，64 位为 8 字节，但具体可用地址位数和进程上限由平台决定。

64 位程序可使用更大地址空间和更多寄存器，但指针及相关结构可能增大，增加缓存和内存占用。协议和文件格式应使用固定宽度整数，不把指针或 size_t 直接写入持久数据。

## 二、CPU 缓存与并发

### 5. CPU 多级缓存如何提高代码和数据访问速度？

**答案：**

CPU 按缓存行把内存块装入 L1／L2／L3，利用时间局部性和空间局部性复用数据。指令缓存和数据缓存通常在较低层分开，更高层可共享，因此代码段和数据段地址相距很远并不妨碍各自被缓存和预取。

硬件预取器可识别顺序／固定步长访问；乱序执行在依赖允许时继续执行其他指令以隐藏延迟。连续数组通常比指针链更友好，跨缓存行随机访问和 cache miss 会显著增加延迟。

### 6. 多线程数据竞争的本质是什么？

**答案：**

多个线程访问同一内存位置，至少一方写，且缺少语言内存模型要求的同步时，就会发生数据竞争；在 C++ 中结果是未定义行为。CPU 缓存一致性只维持缓存行副本的一致状态，不自动提供业务操作的原子性和顺序。

解决方式包括互斥锁、原子操作、线程局部数据、不可变快照、消息队列和单线程所有权。还要区分逻辑竞态：即使每次访问原子，多个步骤组合仍可能违反业务不变量。

### 7. 原子变量在硬件和语言层面如何保证原子性？

**答案：**

语言层面，std::atomic 定义不可分割的访问和相应内存序；硬件可能使用原子读改写指令、缓存一致性协议和必要的屏障实现。

对齐且硬件支持的原子常直接在缓存一致性域中完成；更宽或不支持的类型可能不是 lock-free，可用 `is_lock_free()` 查询。原子性只覆盖该操作，多个原子字段之间的一致更新仍可能需要锁或更复杂协议。

### 8. 锁和原子变量如何选择？lock_guard 为什么能自动解锁？

**答案：**

原子适合计数器、标志和可证明正确的简单状态机；多个字段、复杂不变量或需要等待条件时，锁通常更清楚。高竞争下锁会阻塞／唤醒，原子重试也可能持续争用缓存并浪费 CPU。

lock_guard 构造时调用 mutex.lock，析构时调用 unlock。它利用 RAII，使正常返回和异常栈展开都执行析构。同样模式可封装文件、句柄和内存：构造取得资源，析构释放，并禁用或正确定义复制／移动。

### 9. 什么是伪共享？如何处理？

**答案：**

不同线程修改不同变量，但变量位于同一缓存行时，每次写都会让其他核心的该缓存行副本失效，造成一致性流量和性能下降，这就是伪共享。

可让高频写变量分开存放、按缓存行对齐／填充，或减少共享写。缓存行大小依平台，C++17 提供 `hardware_destructive_interference_size` 作为可用信息；布局修改后要测量实际收益。
