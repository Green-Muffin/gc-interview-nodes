## 一、GPU 架构与执行

### 1. 移动端和 PC 的 GPU 架构有什么不同？

**答案：**

移动设备通常更受功耗、散热和外部内存带宽限制，很多采用统一内存与 Tile 渲染；桌面独显通常有独立显存和更高持续功耗预算。

因此移动端更重视减少附件读写、透明覆盖、资源容量和持续负载。PC 也有 UMA，移动设备也有不同 GPU 能力，实际选型要查询设备并测量，而非仅按平台名判断。

### 2. IMR、TBR 和 TBDR 有什么区别？

**答案：**

IMR 以图元处理和光栅化为主线推进绘制；TBR 先把图元分配到屏幕 Tile，再在片上存储中处理各块，减少中间颜色／深度对外部内存的访问。

TBDR 在 Tile 处理中结合隐藏表面消除，尽量只对可见表面着色。它和“先写 G-buffer 再照明”的 Deferred Shading 不是同一层概念。各架构都有缓存，Tile 数据也不保证永远不写外存。

### 3. TBDR 怎么处理半透明物体？

**答案：**

普通半透明层都可能对最终颜色有贡献，不能像隐藏的不透明表面一样只保留最前层。通常先处理不透明深度，再将透明对象远到近排序并混合。

透明仍能被已有不透明深度剔除。优化重点是减少透明层数、覆盖面积和着色成本；必要时使用 OIT。透明和不透明可分逻辑阶段，不要求一定拆成独立 API render pass。

### 4. SIMT、Subgroup 和分支发散是什么？

**答案：**

GPU 通常以一组 lane 执行相关指令，称 warp、wave 或 subgroup。组内线程走不同分支时，常需按掩码分别执行路径，使部分 lane 暂时闲置。

可通过让相邻线程处理相似数据减少发散；subgroup shuffle、ballot、reduce 等可快速交换或归约数据。组宽依设备和模式，不应固定假定所有 GPU 都是 32 或 64。

### 5. Occupancy 和寄存器压力如何影响性能？

**答案：**

Occupancy 表示执行单元可同时驻留的线程组／wave 数量相对上限。多组工作可在一组等待内存时切换执行，以隐藏延迟。

每线程寄存器或每组共享内存过多会限制驻留量；寄存器溢出还可能产生额外访存。优化时结合寄存器、缓存、活跃 lane 和实际耗时判断，最高占用率不一定是最快配置。

## 二、附件、内存与同步

### 6. RenderPass 和 Subpass 有什么作用？

**答案：**

RenderPass 描述附件、使用方式、加载／保存操作及依赖；Subpass 将相关渲染步骤放在同一实例中，后续阶段可用 Input Attachment 读取先前结果。

典型例子是 G-buffer 写入后进行光照，有机会使数据保留在 Tile 内，减少外部带宽。Input Attachment 通常读取当前像素／样本，不等同于自由 UV 的纹理采样；是否合并取决于容量和驱动实现。

### 7. loadOp、storeOp 和 Transient Attachment 如何优化带宽？

**答案：**

loadOp=LOAD 保留旧内容，CLEAR 用指定值初始化，DONT_CARE 表示不依赖旧内容；storeOp=STORE 保留结果，DONT_CARE 表示后续不需要结果。

只在当前渲染阶段使用的深度或 MSAA 中间附件可标为 transient，并在支持时使用 lazily allocated 内存，给实现省去部分外存分配／访问的机会。若后续 SSAO／SSR 仍需深度，就不能直接丢弃。

### 8. MSAA Resolve 是什么？为什么 Tile GPU 上可能更省带宽？

**答案：**

Resolve 将多样本颜色合成为单样本图像。Tile GPU 可在片上完成 resolve，只保存最终单样本结果，从而避免把全部 MSAA 中间样本先写出再读回。

Vulkan 的 resolve attachment／resolveMode 与 storeOp 独立配置；深度和模板 resolve 还受相应能力限制。收益取决于附件能否保留在 Tile 内。

### 9. Dynamic Rendering 是什么？

**答案：**

Dynamic Rendering 通过 begin／end rendering 在命令中指定附件，减少显式 RenderPass／Framebuffer 对象管理。它在 Vulkan 1.3 进入核心，旧版本可通过相应扩展使用。

基础形式不能逐项替代所有传统 subpass 用法，local read 能力可支持相关局部读取。布局和同步仍需正确管理，接口更简洁不等于自动省去所有依赖。

### 10. Vulkan 的 Memory Type 和主要属性有什么作用？

**答案：**

Memory Type 关联内存 heap 并声明访问属性，分配时还要满足资源允许的类型和对齐。

| 属性 | 作用 |
| --- | --- |
| DEVICE_LOCAL | 适合设备本地访问 |
| HOST_VISIBLE | 可映射给 CPU |
| HOST_COHERENT | 相关主机访问无需显式 flush／invalidate |
| HOST_CACHED | CPU 访问具有缓存 |
| LAZILY_ALLOCATED | 允许按需承诺的特殊附件内存 |

DEVICE_LOCAL 可同时 HOST_VISIBLE。Coherent 解决相关缓存一致性，不替代 CPU／GPU 执行同步；非 coherent 访问需按范围要求 flush／invalidate。

### 11. Staging Buffer 和 Ring Buffer 怎么上传资源？

**答案：**

CPU 写入可映射 staging buffer，通过复制命令传到适合 GPU 使用的资源，然后建立复制写到后续读取的依赖。

Ring Buffer 用不同区间存放多帧上传数据，复用某段前确认 GPU 已用完；长期映射可减少重复 map／unmap。UMA 或合适的小动态数据也可直接使用映射内存，上传策略要结合硬件。

### 12. VMA、子分配和显存别名有什么作用？

**答案：**

子分配在大块 DeviceMemory 中给多个资源分配对齐区间，减少分配次数和碎片；VMA 是提供这些管理能力的常用库，Vulkan 原生也支持子分配。

显存别名让生命周期不重叠的资源复用存储，降低峰值占用。它要求兼容的资源条件和正确同步，GPU 在途使用结束后才能覆盖原存储；RenderGraph 可帮助分析存活区间。

### 13. Vulkan Barrier 如何保证资源读写正确？

**答案：**

Barrier 描述源操作和目标操作之间的执行及内存依赖：源 stage／access 对应之前的访问，目标 stage／access 对应后续访问，必要时还转换图像 layout。

例如 Compute 写 indirect buffer 后，建立 compute shader write 到 draw indirect read 的依赖。范围太窄可能遗漏同步，太宽可能减少并行。Synchronization2 使这些 scope 更容易逐条表达，但不改变正确依赖的必要性。

### 14. Image Layout 是什么？常用 Layout 有哪些？

**答案：**

Layout 描述图像当前允许的访问状态，常见有颜色附件、深度模板附件、只读采样、传输源／目标、GENERAL 和 PRESENT。

图像从附件写入变为纹理读取时，按使用状态转换 layout 并建立依赖。UNDEFINED 可放弃旧内容；GENERAL 可以合法支持相应访问，专用 layout 可能有更好的优化空间。描述符声明、真实 layout 和 usage 必须一致。

### 15. Fence、Binary Semaphore 和 Timeline Semaphore 有什么区别？

**答案：**

Fence 用于主机查询／等待提交完成，常用于帧资源回收。Binary Semaphore 用于 GPU 提交及呈现等操作间的等待／通知，信号由相应等待消费。

Timeline Semaphore 用递增计数值表示完成点，支持 GPU 与主机等待／信号，更方便表达多批任务。使用时仍需保证对象生命周期、值顺序和资源访问依赖。

## 三、命令、绑定与 GPU Driven

### 16. Vulkan 如何进行多线程命令录制？

**答案：**

将渲染任务分给工作线程，各自使用独立 command pool 和 command buffer，完成后按依赖关系提交或由 Primary 执行 Secondary。

Command pool 需要外部同步，按线程分配是常见做法。线程任务过小会抵消并行收益；Secondary 不能直接提交，资源创建／更新也须遵守相关同步要求。

### 17. Descriptor Set 和 Push Constant 分别用来做什么？

**答案：**

Descriptor Set 保存 Shader 访问 buffer、纹理等资源所需的描述，Pipeline Layout 定义 set 接口及 push constant 范围。

Push Constant 适合少量频繁变化的参数，随命令更新；容量上限查设备，不能假定所有设备最多只有 128 字节。Dynamic Descriptor 可在绑定时选择 buffer 偏移，减少为每段数据重复创建描述符。

### 18. Bindless／Descriptor Indexing 的原理是什么？

**答案：**

将大量资源放入描述符数组，让 Shader 根据材质中的索引选择资源，减少 CPU 按对象重新绑定。

需要设备支持相应索引、非一致访问和绑定特性；未使用位置可不绑定的能力不意味着可以访问无效元素。资源数量、生命周期和同步仍由应用管理。

### 19. PSO 和 Pipeline Cache 有什么作用？如何控制变体数量？

**答案：**

Pipeline／PSO 将程序及多种渲染状态组织成可绑定对象，降低运行时重复配置成本。Pipeline Cache 保存可复用的创建结果，有助于减少重复创建耗时。

通过合并等价状态、使用支持的动态状态、把材质数值留在资源数据中，可减少变体。缓存受设备／驱动兼容性约束，不能保证任意新组合都没有首次创建成本。

### 20. Async Compute 和独立 Transfer Queue 怎么优化性能？

**答案：**

将与图形工作依赖较少的计算或复制任务放到相应队列，尝试与主渲染重叠，用 semaphore 连接结果消费。

收益来自隐藏等待或利用空闲执行资源。多个 API 队列不保证独立硬件，Compute／Graphics 还可能争用带宽和着色单元，因此需测量整帧收益，并处理跨 queue family 的所有权。

### 21. RenderGraph 的原理和作用是什么？

**答案：**

将一帧表示为 Pass 节点与资源依赖边。根据声明分析执行顺序、资源存活区间、barrier、layout、临时资源和别名，还可删除无输出用途的 Pass。

它降低手写调度的复杂度。历史纹理、外部资源和副作用必须明确声明，否则图无法推导正确的依赖。

### 22. GPU Driven 渲染怎么实现？

**答案：**

GPU 读取场景实例数据，用 Compute 做视锥／遮挡剔除、LOD 选择和可见列表压缩，再写 indirect draw 参数与计数，由后续绘制直接消费。

这样可降低 CPU 逐对象提交负担，无需每帧回读可见列表。Compute 写到 indirect read 需要同步，输入与命令缓冲还需正确管理多帧在途。GPU 剔除和命令生成本身也有成本。

### 23. Mesh Shader、VRS 和 Multiview 各有什么作用？

**答案：**

Mesh Shader 以工作组／meshlet 组织顶点和图元输出，便于细粒度剔除；可选 Task Shader 分发几何工作。

VRS 调整片元着色的空间频率，低细节区域可用较粗频率；几何覆盖和深度采样不必同步减少。Multiview 一次组织多个视图，减少重复提交，常用于 VR；每视图的实际变换和渲染仍有成本。

## 四、移动端实践与性能优化

### 24. 移动端实现延迟渲染需要注意什么？

**答案：**

重点是 G-buffer 数量与格式、外部带宽、Tile 容量、多光源收益和透明处理。

可打包材质参数、编码法线、减少附件读写，并利用 subpass／local read。透明通常另走 Forward，MSAA 可行但附件和边缘光照成本更高。ASTC／ETC2 是资产纹理压缩方案，不能直接当成普通实时 G-buffer 附件格式。

### 25. 哪些全局光照方案适合移动端？

**答案：**

优先考虑静态 Lightmap、动态物体光照探针和预过滤 IBL；需要局部动态细节时可加入低分辨率 AO／SSGI 或动态探针。

LPV、SSR 和光追也可在预算允许的设备上使用，常通过降分辨率、减少样本／传播次数、降低更新频率和时间重建控制成本。Lightmap 仍有存储和采样开销，动态方案需持续负载验证。

### 26. 移动设备如何实现镜面反射？

**答案：**

- **反射探针／Cubemap**：采样便宜，适合多数环境反射；局部视差和动态物体表现有限。
- **平面反射**：镜像相机渲染反射图，适合镜子、水面；额外绘制成本较高，可降低分辨率和更新频率。
- **SSR**：复用屏幕颜色和深度，细节随场景更新；看不到离屏与隐藏物体，需要探针回退。
- **光线反射**：功能与预算允许时用于局部高质量反射，通常配合低采样和降噪。

### 27. 顶点处理和片元着色开销过高，分别如何优化？

**答案：**

顶点侧：减少不可见几何、使用 LOD、优化蒙皮和属性数据，预计算公共矩阵，利用索引复用。顶点属性槽不足时先打包／删除冗余数据，必要时用 buffer pulling。

片元侧：减少 Overdraw 和透明覆盖，简化纹理采样、材质与灯光，将合适的屏幕效果降分辨率，利用深度剔除。

先看 GPU 捕获和对照实验确定瓶颈。实例化主要减少提交，不会自动消除每实例顶点工作；程序化噪声改变高度也不等于减少面数。

### 28. 纹理和带宽开销如何优化？

**答案：**

选择设备支持的 BC／ETC／ASTC 等资产格式，按用途设置尺寸和 Mip；减少不必要的高精度附件、MSAA 存储以及全屏 Pass 的往返读写。

对法线、遮罩和颜色使用正确格式／sRGB 设置；对临时附件配置合理 load/store。动态分辨率可降低像素与带宽成本，但需要配合重建和画质验证。

### 29. 大世界和城市场景如何优化？

**答案：**

按空间分块流式加载，设置资源预算；结合视锥与遮挡剔除、LOD／HLOD、重复物体实例化，减少远处几何、动画和阴影更新。

城市建筑遮挡强，可利用预计算可见性或 Hi-Z；灯光用分块／簇列表，反射用探针和 SSR 组合。大块合并会削弱剔除粒度，需权衡；突然转向和快速移动应作为加载压力场景。

### 30. 虚拟纹理的原理是什么？

**答案：**

把逻辑纹理分成页，用页表映射到有限的物理纹理缓存；根据采样反馈和预取策略加载所需页面，淘汰低优先级页面。

优点是只驻留部分超大纹理数据；代价是反馈、页表、IO 和上传。缺页时应使用粗 Mip 回退，并处理页面边界过滤，不能阻塞渲染等待每个页面到达。

## 五、显示与帧同步

### 31. 双缓冲、三缓冲和 VSync 有什么区别？

**答案：**

双缓冲让 GPU 在后台图像绘制，再将完成图像用于显示；三缓冲增加可轮转图像，降低因没有空闲缓冲导致的等待。

VSync 控制呈现时机，避免扫描显示期间切换图像造成撕裂。缓冲数量本身不保证无撕裂；更多在途帧可提高吞吐，也可能增加排队和输入延迟。

### 32. FIFO、MAILBOX、IMMEDIATE 和 VRR 是什么？

**答案：**

FIFO 按队列在刷新时呈现；MAILBOX 保留较新的待呈现候选，替换旧候选；IMMEDIATE 允许立即切换图像，可能撕裂。具体支持需查询，MAILBOX 不等于固定三张图像。

VRR 在支持范围内让显示刷新节奏跟随帧产生速度，减轻撕裂和卡顿。评价时既看 FPS，也看帧时间稳定性、功耗与输入到显示延迟。

### 33. 如何区分 CPU、GPU 和热降频造成的卡顿？

**答案：**

记录主线程／渲染线程、GPU、帧间隔、分配与温度变化。CPU 忙时查逻辑和提交，GPU 忙时逐项调整分辨率、材质、阴影和透明效果；等待标记高还可能来自限帧或呈现同步。

固定场景和画质，分别观察冷启动与持续运行。性能随运行时间和温度下降时，应检查功耗／频率，并设计稳定帧率预算，而不是只优化一次短跑结果。
