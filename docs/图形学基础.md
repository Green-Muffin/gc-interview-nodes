## 一、流水线与可见性

### 1. 怎样讲清光栅化管线？

**问题：** 把场景中的几何、材质、光照转换为二维图像。

典型流程：应用侧准备资源与绘制命令 → 顶点处理 → 可选细分／几何阶段 → 图元装配与齐次裁剪 → 透视除法、视口映射 → 光栅化 → 片元处理 → 深度／模板／混合 → 帧缓冲。

这是功能模型，不是所有硬件固定的时间顺序：部分测试可提前，Tile 架构会分块，Compute／Mesh Shader 也有其他入口。应用侧负责场景更新、可见性、排序及资源状态；一帧通常包含阴影、主视图、后处理等多个 Pass。

顶点着色器输出裁剪位置和属性；片元着色器读取插值属性并产生颜色等结果。`SV_Position`／`gl_Position` 的具体含义需结合所在阶段和 API，不能把片元阶段的位置输入仍当作原始裁剪坐标。

### 2. Pixel、Sample 与 Fragment 有什么区别？

Pixel 是图像网格位置，Sample 是覆盖、深度等操作的采样位置；Fragment 是图元覆盖产生的候选片段。多个图元可为同一像素产生多个片段，片段也可能被丢弃或测试淘汰。

MSAA 下一个像素有多个采样位置，着色调用数量不必等于采样数。辅助执行通道还可能参与导数计算而不写入最终像素。因此“一个片元就是最终一个像素”不准确。

### 3. 坐标变换、View Matrix 和投影怎样衔接？

采用**列向量**约定时：`clip = P × V × M × position`，随后 `ndc = clip.xyz / clip.w`，再映射到视口。行向量约定须调整顺序；矩阵存储的行／列主序与数学乘法约定是两个问题。

View Matrix 是相机世界变换的逆。若相机世界刚体变换为旋转 R、平移 t，则视图变换是旋转 `Rᵀ` 和平移 `−Rᵀt`；朝向 −Z 或 +Z 是约定，不是所有 API 的强制选择。

正交投影的平行线保持平行，不产生近大远小。常见透视投影中 `w` 与观察空间深度的绝对尺度成比例，物体越远通常 w 越大，除以 w 后越小；原材料中的远近关系已更正。

对于对称视锥：`top = near × tan(fovY/2)`，`right = top × aspect`。近平面距离应为正的几何距离，具体矩阵中的符号依坐标约定。

### 4. 为什么先在齐次空间裁剪，再做透视除法？

齐次裁剪可正确处理跨越视锥边界和相机附近的图元，避免先除以接近零或负的 w 造成错误投影。裁剪产生的新顶点须带上相应属性。

常见 OpenGL 默认深度范围为 `−1 ≤ z/w ≤ 1`，Vulkan／Direct3D 常见为 `0 ≤ z/w ≤ 1`；扩展和状态可改变某些约定，屏幕 Y 方向也须单独确认。裁剪测试用的是对应的齐次不等式，不是把每个顶点强行夹到 NDC 边界。

Sutherland–Hodgman 是逐裁剪平面处理多边形的经典方法：根据边的两端内外关系保留端点或插入交点。

### 5. 覆盖测试与重心插值如何工作？

以边函数判断采样点位于三条有向边的哪一侧，在三角形包围盒内确定覆盖；共享边用 top-left 等一致规则避免重复覆盖或裂缝。

重心坐标满足 `λ₀ + λ₁ + λ₂ = 1`。屏幕空间线性插值只适用于相应数据；透视投影后的 UV 等通常需做透视校正：

```text
a = (λ₀ a₀/w₀ + λ₁ a₁/w₁ + λ₂ a₂/w₂)
    / (λ₀/w₀ + λ₁/w₁ + λ₂/w₂)
```

插值法线使用前通常需要归一化。深度、flat、noperspective 等各有规则，不能把所有属性一律按同一个公式理解。

### 6. 剔除、裁剪与“小三角形剔除”有哪些边界？

| 方法 | 判断内容 | 注意 |
| --- | --- | --- |
| 视锥剔除 | 包围体是否完全处于视锥外 | 常在对象／批次级处理 |
| 背面剔除 | 投影后绕序与正反面约定 | 不等于一律对顶点法线做视线点积 |
| 遮挡剔除 | 包围体是否被已有遮挡完全覆盖 | 需保守判断，历史深度可能失效 |
| 裁剪 | 图元与裁剪体相交后保留哪部分 | 可产生新顶点 |
| 亚像素优化 | 极小图元是否可能覆盖样本 | 小于一像素面积仍可能贡献，不能无条件丢弃 |

Hi-Z 用层级深度保守排除区域。应根据深度方向及测试目的选择 min／max 或区间归约，不能永远固定“存最小值”。

### 7. 深度、模板与 Alpha Clip 如何配合？

深度测试决定候选深度是否通过，深度写入决定通过后是否更新缓冲，两者独立。模板测试及其失败／深度失败／通过操作可做遮罩、Portal、描边或阴影体；位数依附件格式，不是每个片元私有一份固定整数。

Alpha Clip 在着色逻辑中按阈值 discard，适合镂空；Alpha Blend 组合颜色，适合半透明。先测试还是先着色受到提前测试模式、写深度、副作用等约束，不能背成所有平台唯一固定次序。

### 8. Early-Z、Late-Z 与深度预通道何时有用？

Early-Z 在昂贵着色之前排除被挡住的工作；Late-Z 根据最终着色结果执行相关测试／更新。discard、深度输出和副作用会限制提前测试或提前**写入**，但并非出现 discard 就必然完全关闭所有早期剔除。

透明物体即使不写深度，也可能借用已有不透明深度做提前排除。深度预通道先确定可见面，适合某些高 Overdraw、重着色负载；代价是额外几何与提交工作，在 Tile GPU 上也可能得不偿失。

### 9. 混合与绘制顺序怎样选择？

| 模式 | 常见 RGB 公式 | 用途／限制 |
| --- | --- | --- |
| 直通 Alpha | `Cs × αs + Cd × (1−αs)` | 通常依赖远到近排序 |
| 预乘 Alpha | `Cs_pre + Cd × (1−αs)` | 源 RGB 已乘 alpha，不能再乘一次 |
| 加法 | `Cs + Cd` | 光晕、能量叠加；透明度权重另约定 |
| 乘法 | `Cs × Cd` | 染色、变暗等艺术效果 |

理想加法／乘法具有交换性，但深度写入、裁剪、饱和、精度与其他状态仍会影响实际绘制顺序。普通不透明颜色在正确深度条件下通常不依赖排序，前到后排序却可能减少着色成本。

透明物体相交时对象级排序不足。Depth Peeling 可保留多层，Weighted Blended OIT 以近似换性能；OIT 并不意味着所有方案都精确。

## 二、采样与抗锯齿

### 10. 走样的根源与“先滤波再采样”是什么？

有限采样无法唯一恢复超出采样带宽的信号，出现锯齿、摩尔纹、闪烁甚至车轮倒转。带限信号满足相应采样条件时才可重建；真实几何边界通常并不带限，需要像素足迹上的滤波积分。

预滤波减少会混叠的高频，再采样；采样之后的模糊不能恢复已经丢失的信息。实时方法用空间、时间、多重覆盖采样和重建近似这个过程，均有成本与偏差。

### 11. SSAA、MSAA、FXAA、SMAA 各处理什么？

| 方法 | 核心做法 | 优点 | 局限 |
| --- | --- | --- | --- |
| SSAA | 更密集着色后滤波到目标分辨率 | 可处理较多类型混叠 | 像素工作和缓冲成本高 |
| MSAA | 增加覆盖、深度等采样，常复用着色 | 擅长几何边缘 | 不能完整消除材质／高光混叠 |
| FXAA | 从图像找边缘并平滑 | 接入简单、成本可控 | 可能模糊细节，缺失几何信息 |
| SMAA | 形态边缘分析与权重重建 | 边缘处理更精细 | 具体变体可能含空间或时间采样 |

4× MSAA 是每像素 4 个样本，不是 4×4；SSAA 增加像素工作不意味着把所有顶点阶段完整执行四遍。MSAA 成本也不是随倍率指数增长，颜色／深度存储通常随样本数增加，压缩和架构会改变实际代价。

### 12. MSAA 与透明、延迟渲染真的“不兼容”吗？

MSAA 可用于多采样 G-buffer，只是存储、边缘光照与 resolve 更复杂。把不同表面的法线、材质先随意平均再着色会出错；可在边缘按样本处理，成本更高。

普通 Alpha Clip 不会自动产生正确的部分覆盖，可结合 alpha-to-coverage；sample shading 等又会改变着色频率。Alpha Blend 可以作用于多采样目标，但不解决透明排序本身。

因此应回答“支持条件与成本”，不能写成“G-buffer 绝不能 MSAA”。移动端片上 resolve 的实现见硬件篇。

### 13. TAA 如何工作，拖影怎样控制？

步骤是投影抖动 → 当前帧着色 → 利用运动矢量重投影历史 → 检查历史有效性 → 裁剪／钳制历史 → 自适应混合。

运动矢量需涵盖相机、对象变换和适用的蒙皮变形，并统一抖动、分辨率和坐标约定。遮挡显露、反射运动、透明混合及粒子会破坏一对一对应；并非简单换成“每像素速度”就全部解决。

降低历史权重可减少拖影但增加噪声；过强钳制会丢细节，锐化也可能放大闪烁。透明与体积效果可使用专用重投影、反应遮罩或其他滤波，并非完全无法时间累积。时间超分与光追降噪见实时渲染篇。

## 三、基础光照与着色

### 14. 光源类型与距离衰减如何解释？

平行光近似远处光源，点光源从一点向外发射，聚光灯加入角度分布，面光源有空间范围，带来有限尺寸高光与半影。

理想点光源沿给定方向的辐射强度 I，对距离 r、入射角 θ 的小面元产生 `E = I × max(cosθ,0) / r²`。这是辐照度的衰减，不是辐亮度沿真空光路也按同样公式衰减。

`1/(k₀+k₁r+k₂r²)` 可用于经验控制；物理工作流也常对平方反比衰减做光源尺寸与有限作用范围处理。艺术控制应和物理量定义区分。

### 15. Lambert、Phong、Blinn–Phong 的联系是什么？

Lambert BRDF 为 `ρ/π`，入射投影面积带来 `max(N·L,0)`。Lambertian 的出射辐亮度与观察方向无关，不代表任意真实粗糙材质都完全均匀。

Phong 使用 `max(R·V,0)^p`，其中 `R = 2(N·L)N−L`；Blinn–Phong 使用 `H = normalize(L+V)` 与 `max(N·H,0)^p`。两种指数并不直接对应相同粗糙度；经验高光也不自动能量守恒。

Half-Lambert 将点积重新映射以提亮背光，是艺术处理。常量 ambient 粗略补暗部；IBL 和探针提供更有方向性的间接光。所有方向需在同一坐标空间并正确归一化。

### 16. Flat、Gouraud、Phong Shading 与 Phong 高光有何区别？

Flat 用面级不连续属性形成面片感；Gouraud 在顶点求光照后插值颜色；Phong Shading 插值法线并在片元求光照，能更好捕捉三角形内部的高光。

Phong Shading 描述**求值粒度**，Phong 反射模型描述**光照公式**，不是同一个概念。使用面法线也不意味着整个大三角形在点光源下必须每处同色，实际还取决于位置是否逐片元求值。

### 17. 多光源叠加与能量预算要注意什么？

经验模型常写成 ambient 加各灯的 diffuse／specular、衰减和可见性。光能可在线性域叠加，但多次添加同一个间接光项或未约束漫反射与高光会导致过亮。

PBR 用 BRDF／BSDF 约束材质，光照积分仍须选择合适近似。基础模型便于理解法线和视线关系，不能据此把所有真实材质归为“一个漫反射加一个任意高光”。

## 四、纹理与表面细节

### 18. 点、双线性与三线性过滤有什么区别？

最近邻取单个纹素；双线性对同一层邻近四个纹素加权；常说的三线性是两层 Mip 各双线性，再按 LOD 混合，并非三维空间的八点插值。

OpenGL 放大过滤只支持 NEAREST／LINEAR，Mip 组合属于缩小过滤。双线性改善放大方块感，却不能替代缩小时足够的预滤波。

### 19. Mipmap 的层数与存储怎样计算？

正尺寸二维纹理完整 Mip 链的最大层数为 `floor(log₂(max(W,H))) + 1`，资源可仅分配部分层；图像不会仅因创建了纹理就自动生成全部层内容。

对方形二维纹理，宽高每层约减半，总像素量 `1 + 1/4 + 1/16 + … ≈ 4/3`，约增加三分之一。1024×1024 RGBA8 基础层为 4 MiB，完整链约 5.33 MiB；非方形、块压缩和小层对齐会改变实际值。

### 20. Mip 层级怎样由屏幕导数估算？

若 UV 已归一化，先按纹理宽高转成纹素尺度：

```text
dx = (W × ddx(u), H × ddx(v))
dy = (W × ddy(u), H × ddy(v))
rho = max(length(dx), length(dy))
lod ≈ log2(rho)
```

这是常见各向同性近似；实际还包含范围限制、bias 和采样器规则。遗漏 W、H 会导致单位错误。隐式导数通常依赖相邻片元执行；非一致控制流要小心，可按需要使用显式梯度／LOD。

### 21. 各向异性过滤如何改善斜视纹理？

斜视时像素在纹理域的足迹可能细长，单一方形 Mip 核会模糊较短方向。AF 用更多采样近似该方向性足迹，具体方向由 UV 映射和投影决定，不只是沿世界空间视线取样。

倍率是实现受约束的质量参数，不等于每次调用精确执行 N 次纹理指令；它不会额外创建一套独立纹理，主要成本是采样与带宽。Mip 链与 AF 常配合，但资源配置和采样支持仍以设备为准。

### 22. Cubemap 与法线贴图怎样读取？

Cubemap 用方向选择六面中的一个，再按 API 面朝向约定换算二维坐标；可用于天空、环境反射和 IBL。跨面过滤、接缝与预过滤方法会影响质量。

切线空间法线通常从纹理值解码到 `[-1,1]`，通过 TBN 基变换至着色空间后归一化。TBN 须处理切线手性、镜像 UV、非均匀缩放及与烘焙工具的一致性；切线贴图不能无条件复用到任意网格。

BC5 等常保存两个分量并在适用的正半球约定下重建 Z。法线与粗糙度属于数据，通常不做 sRGB 解码；对象空间法线贴图也是合法方案，只是变形和复用约束不同。

### 23. 法线、凹凸、位移与压缩分别改变什么？

凹凸从高度梯度扰动法线，法线贴图直接保存方向，通常不改变轮廓；位移真正修改几何，需要足够细分或其他求交方式；视差类方法主要修改采样路径，仍有遮挡和轮廓限制。

G-buffer 法线可用八面体编码压到两个分量，格式可在精度与带宽间选择，`RG16_UNORM` 只是方案之一。磁盘纹理压缩和渲染目标编码不是同一件事，具体 BC／ETC／ASTC 支持见硬件篇。

## 五、阴影基础

### 24. Shadow Map 的步骤、Acne 与 Peter Panning 是什么？

先从光源渲染最近深度，再把接收点投到相同空间，以一致的深度定义和比较方向判断遮挡。方向光常用正交投影，聚光灯常用透视投影；并非所有深度值都是线性世界距离。

有限分辨率、斜面采样和数值误差可造成自阴影 Acne。深度／斜率／法线偏移可缓解，但过量会使阴影脱离接触点，即 Peter Panning。分辨率走样与比较误差是不同问题，滤波不能万能解决两者。

基础阴影 Pass 的成本仍受场景复杂度、绘制次数与遮挡物影响，不能说 Shadow Mapping 与几何数量无关。

### 25. Shadow Volume、本影、半影与高级阴影如何衔接？

Shadow Volume 根据遮挡轮廓构造体积并利用模板计数等方式判断遮挡，涉及闭合几何、裁剪及填充成本。本影／半影描述光源全部／部分被挡住的区域，不是独立算法名称。

PCF 平滑比较结果，PCSS 估计接触硬化，VSM／VSSM／MSM 用统计矩，SDF 用距离场近似；CSM 分配大场景阴影分辨率。完整步骤、公式和取舍集中在 [高质量实时渲染](高质量实时渲染.md)，本篇不重复展开。

## 六、颜色与动态范围

### 26. Z-fighting 与 Reversed-Z 应怎样理解？

传统透视深度通常是 `a + b/z`，有限精度可能无法区分近共面表面。适当增大 Near、合理裁剪范围、调整几何或深度偏移有帮助，具体策略依使用场景。

Reversed-Z 常把近处映为 1、远处映为 0，清深度为 0，比较改为 Greater／GreaterEqual。其显著收益来自**浮点深度**在接近零处更密的表示与透视映射相配合；固定点深度只是倒转同样间隔，并不会因此普遍获得相同精度提升。Hi-Z 等相关逻辑也要同步调整。

参考：[NVIDIA：深度精度](https://developer.nvidia.com/blog/visualizing-depth-precision/)。

### 27. 为什么在线性域做光照，sRGB 与 Gamma 2.2 有何不同？

sRGB 包含原色、白点和传递函数，不只是一个指数。其解码是分段函数；`linear ≈ encoded^2.2` 只是粗略近似，暗部差别尤其明显。

正确工作流是颜色纹理解码 → 线性光照／混合 → 显示变换与输出编码。法线、深度、金属度、粗糙度等数据纹理不按颜色解码。还应避免重复编码，确认渲染目标的硬件 sRGB 转换状态。

人眼对亮度的响应不是一条可直接照搬的简单幂函数，也没有“统一能分辨 100 级暗部、20 级亮部”的通用结论。

### 28. HDR、曝光、Tone Mapping 与色彩空间是什么关系？

HDR 场景值可超过 1，常用浮点格式保存；RGBA16F 很常见，但不是唯一方案。LDR 也不必定义为所有情况下只有 8 位。

曝光缩放场景值，色调映射把亮度范围适配显示器，色域映射处理超出输出色域的颜色，传递函数完成输出编码。SDR 和 HDR 显示目标不同，不能统一写成“HDR 最后都转 LDR”。

Bloom、景深、运动模糊通常需考虑 HDR 数据，但“所有后处理必在同一个阶段”也不成立。显示相关调色、UI 合成与锐化等应按所用管线约定安排；物理相机和同色异谱见数学几何篇。
