## 一、复杂度与排序

### 1. 常见排序算法的复杂度和稳定性如何比较？

**答案：**

稳定排序保留“比较相等”的元素原有顺序；原地与稳定不是同一个概念。下表描述常见实现，空间不含输入存储。

| 算法 | 平均时间 | 最坏时间 | 额外空间 | 常见稳定性 |
| --- | --- | --- | --- | --- |
| 冒泡（含提前结束） | O(n²) | O(n²) | O(1) | 稳定 |
| 直接插入 | O(n²) | O(n²) | O(1) | 稳定 |
| 选择 | O(n²) | O(n²) | O(1) | 通常不稳定 |
| 希尔 | 取决于增量序列 | 取决于增量序列 | O(1) | 通常不稳定 |
| 快速 | O(n log n) | O(n²) | 平均 O(log n) 栈，朴素最坏 O(n) | 通常不稳定 |
| 归并（数组版） | O(n log n) | O(n log n) | O(n) | 可稳定 |
| 堆排序 | O(n log n) | O(n log n) | O(1) | 通常不稳定 |

计数排序约 O(n+k)，适合可控键域；桶排序依赖分布；基数排序依赖位数与桶基数，不能脱离输入条件宣称线性时间优于比较排序。选择时考虑近乎有序、小规模、重复值、内存与稳定性要求。

### 2. 快速排序何时退化？选中间下标能保证 O(n log n) 吗？

**答案：**

快速排序按 pivot 分区，再处理左右部分。分区长期均衡时约 O(n log n)；若每次只有一个元素被划出，形成 n、n−1、n−2 的递归规模，时间可退化为 O(n²)。

“中间下标的值”不一定是数值中位数。随机 pivot、三数取中能改善常见情况，但不提供对任意输入的最坏复杂度保证；大量重复键可使用三路分区，深度超限转堆排序的 introsort 可控制最坏情况。

面试写法要说清区间约定、指针前进规则与重复元素处理。只递归较短分区、循环处理较长分区，可降低递归栈风险。

## 二、搜索与寻路

### 3. DFS 与 BFS 有什么区别？时间和空间复杂度是多少？

**答案：**

DFS 使用递归或显式栈向深处探索，适合连通分量、拓扑／回溯等；BFS 使用队列按层扩展，在无权图或所有边权相等时可求最少边数路径。

邻接表表示下，访问整张图通常都是 O(V+E)，额外空间可达 O(V)。邻接矩阵扫描的成本不同。BFS 常在入队时标记 visited，避免同一节点被重复入队；DFS 递归深度过大可改显式栈。

DFS 找到的第一条路径一般不保证最短。带权图不能仅换成普通 BFS，需要结合权重性质选择算法。

### 4. A* 的核心公式、步骤与最优性条件是什么？

**答案：**

`f(n) = g(n) + h(n)`：g 为起点到当前节点已知路径代价，h 为到目标的估计代价。用优先队列维护候选节点，父指针用于回溯路径。

```text
g[start] = 0，其余为无穷大；将 start 入队
循环直到队列为空：
    取 f 最小的有效条目；跳过过期条目
    若为 goal，则沿 parent 还原路径
    对每个可达邻居 v：
        tentative = g[current] + cost(current, v)
        若 tentative < g[v]：
            更新 g[v] 和 parent[v]
            以 g[v] + h(v) 入队；按策略重新开放改进的节点
队列为空仍未到达目标，则不可达
```

在常见非负边权条件下，不高估的启发式有助于保证最优性；图搜索若不重开已关闭节点，通常还需一致性条件 `h(u) ≤ cost(u,v)+h(v)`。`h=0` 对应 Dijkstra。

四方向单位网格常用曼哈顿距离，八方向移动需采用与对角代价匹配的估计。障碍角落能否穿越、动态障碍、不可达目标和代价单位都需明确，不能只背公式。

### 5. A* 在游戏中如何优化？如何与 AOI 区分？

**答案：**

寻路可缓存静态导航数据、复用容器、限制单帧搜索预算，必要时采用分层导航或适合特定地图的算法。优先优化邻居生成、堆操作与无效搜索，并管理地图版本变化造成的过期结果。

AOI 关注“哪些实体彼此相关”，寻路关注“如何到达目标”，二者问题不同；网格或空间索引可以复用思路，不能把 A* 当作所有邻近查询的解决方案。

## 三、手写与游戏算法

### 6. 如何求第 n 个斐波那契数？如何处理溢出？

**答案：**

先明确 `F(0)=0、F(1)=1`。朴素递归重复计算，时间呈指数增长；缓存或迭代可在线性次数内完成。下面使用 BigInteger 表达任意精度结果，n 为非负整数。

```csharp
static System.Numerics.BigInteger Fibonacci(int n)
{
    if (n < 0) throw new System.ArgumentOutOfRangeException(nameof(n));
    System.Numerics.BigInteger a = 0, b = 1;
    for (int i = 0; i < n; i++)
    {
        var next = a + b;
        a = b;
        b = next;
    }
    return a;
}
```

迭代需要 O(n) 次加法、固定数量的大整数变量，但大整数的位数随 n 增长，不能把位复杂度也当作 O(n) 时间／O(1) 空间。快速倍增可以减少递推层数。

### 7. 如何实现“相同颜色四连通，达到三格就消除”？

**答案：**

先明确规则：这是**连通块消除**，不是只匹配连续横线／竖线的传统三消。原材料在递归返回时恢复格子，又没有正确使用 visited 阻止重复访问，容易重复计数。

下面约定 `None` 是空格；0 可以是合法颜色。一次扫描先找出所有符合条件的连通块，随后统一清除，不在搜索中回溯恢复已访问状态。

```python
def clear_components(board, min_size=3):
    if min_size < 1:
        raise ValueError("min_size must be positive")
    if not board:
        return 0
    rows, cols = len(board), len(board[0])
    if any(len(row) != cols for row in board):
        raise ValueError("board must be rectangular")
    visited, doomed = set(), set()
    for r in range(rows):
        for c in range(cols):
            if board[r][c] is None or (r, c) in visited:
                continue
            color = board[r][c]
            stack, group = [(r, c)], []
            visited.add((r, c))
            while stack:
                x, y = stack.pop()
                group.append((x, y))
                for nx, ny in ((x-1,y), (x+1,y), (x,y-1), (x,y+1)):
                    if (0 <= nx < rows and 0 <= ny < cols
                            and (nx, ny) not in visited
                            and board[nx][ny] == color):
                        visited.add((nx, ny))
                        stack.append((nx, ny))
            if len(group) >= min_size:
                doomed.update(group)
    for r, c in doomed:
        board[r][c] = None
    return len(doomed)
```

时间和辅助空间均为 O(行数 × 列数)。如果规则含下落、补充和连锁，应在这一轮完成后分阶段执行，再重新检测。

### 8. 传统三消与连通块消除有什么区别？

**答案：**

传统三消通常检查横向／纵向连续同色段，长度达到阈值后做标记，再一次性清除。L 形三个同色格可能是一个三格连通块，却没有任何连续三格直线，因此不能用同一个连通块算法直接替代。

推荐流程：扫描行列形成待消除集合 → 统一清除并计分 → 下落 → 补充 → 下一轮检测。交叉位置只计一次；特殊棋子、交换有效性与随机补充规则另行定义。

### 9. 如何手写 strcpy？为什么返回目标首地址？

**答案：**

下面保留经典 C 接口的调用契约：指针有效、源以空字符结尾、目标容量足够且两段内存不重叠。原签名没有容量参数，函数无法自行保证目标空间足够。

```c
char *copy_string(char *dest, const char *src)
{
    char *begin = dest;
    while ((*dest++ = *src++) != '\0')
    {
    }
    return begin;
}
```

返回首地址便于调用者继续使用目标字符串或组合表达式，而不是返回已经移动到末尾的指针。工程接口可显式接收容量并返回状态；重叠复制需另外设计，不可直接套用这个循环。
