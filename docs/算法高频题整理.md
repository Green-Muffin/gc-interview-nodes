## 一、复杂度与排序

### 1. 常见排序算法的复杂度和稳定性如何比较？

**答案：**

稳定排序保留“比较相等”的元素原有顺序；原地与稳定不是同一个概念。下表描述常见实现，空间不含输入存储。

| 算法 | 平均时间 | 最坏时间 | 额外空间 | 常见稳定性 |
| --- | --- | --- | --- | --- |
| 冒泡（含提前结束） | O(n²) | O(n²) | O(1) | 稳定 |
| 直接插入 | O(n²) | O(n²) | O(1) | 稳定 |
| 选择 | O(n²) | O(n²) | O(1) | 通常不稳定 |
| 希尔 | 取决于增量序列 | 取决于增量序列 | O(1) | 通常不稳定 |
| 快速 | O(n log n) | O(n²) | 平均 O(log n) 栈，朴素最坏 O(n) | 通常不稳定 |
| 归并（数组版） | O(n log n) | O(n log n) | O(n) | 可稳定 |
| 堆排序 | O(n log n) | O(n log n) | O(1) | 通常不稳定 |

计数排序约 O(n+k)，适合可控键域；桶排序依赖分布；基数排序依赖位数与桶基数，不能脱离输入条件宣称线性时间优于比较排序。选择时考虑近乎有序、小规模、重复值、内存与稳定性要求。

### 2. 快速排序何时退化？选中间下标能保证 O(n log n) 吗？

**答案：**

快速排序按 pivot 分区，再处理左右部分。分区长期均衡时约 O(n log n)；若每次只有一个元素被划出，形成 n、n−1、n−2 的递归规模，时间可退化为 O(n²)。

“中间下标的值”不一定是数值中位数。随机 pivot、三数取中能改善常见情况，但不提供对任意输入的最坏复杂度保证；大量重复键可使用三路分区，深度超限转堆排序的 introsort 可控制最坏情况。

面试写法要说清区间约定、指针前进规则与重复元素处理。只递归较短分区、循环处理较长分区，可降低递归栈风险。

## 二、搜索与寻路

### 3. DFS 与 BFS 有什么区别？时间和空间复杂度是多少？

**答案：**

DFS 使用递归或显式栈向深处探索，适合连通分量、拓扑／回溯等；BFS 使用队列按层扩展，在无权图或所有边权相等时可求最少边数路径。

邻接表表示下，访问整张图通常都是 O(V+E)，额外空间可达 O(V)。邻接矩阵扫描的成本不同。BFS 常在入队时标记 visited，避免同一节点被重复入队；DFS 递归深度过大可改显式栈。

DFS 找到的第一条路径一般不保证最短。带权图不能仅换成普通 BFS，需要结合权重性质选择算法。

### 4. A* 的核心公式、步骤与最优性条件是什么？

**答案：**

`f(n) = g(n) + h(n)`：g 为起点到当前节点已知路径代价，h 为到目标的估计代价。用优先队列维护候选节点，父指针用于回溯路径。

```text
g[start] = 0，其余为无穷大；将 start 入队
循环直到队列为空：
    取 f 最小的有效条目；跳过过期条目
    若为 goal，则沿 parent 还原路径
    对每个可达邻居 v：
        tentative = g[current] + cost(current, v)
        若 tentative < g[v]：
            更新 g[v] 和 parent[v]
            以 g[v] + h(v) 入队；按策略重新开放改进的节点
队列为空仍未到达目标，则不可达
```

在常见非负边权条件下，不高估的启发式有助于保证最优性；图搜索若不重开已关闭节点，通常还需一致性条件 `h(u) ≤ cost(u,v)+h(v)`。`h=0` 对应 Dijkstra。

四方向单位网格常用曼哈顿距离，八方向移动需采用与对角代价匹配的估计。障碍角落能否穿越、动态障碍、不可达目标和代价单位都需明确，不能只背公式。

### 5. A* 在游戏中如何优化？如何与 AOI 区分？

**答案：**

寻路可缓存静态导航数据、复用容器、限制单帧搜索预算，必要时采用分层导航或适合特定地图的算法。优先优化邻居生成、堆操作与无效搜索，并管理地图版本变化造成的过期结果。

AOI 关注“哪些实体彼此相关”，寻路关注“如何到达目标”，二者问题不同；网格或空间索引可以复用思路，不能把 A* 当作所有邻近查询的解决方案。

## 三、手写与游戏算法

### 6. 如何求第 n 个斐波那契数？如何处理溢出？

**答案：**

先明确 `F(0)=0、F(1)=1`。朴素递归重复计算，时间呈指数增长；缓存或迭代可在线性次数内完成。下面使用 BigInteger 表达任意精度结果，n 为非负整数。

```csharp
static System.Numerics.BigInteger Fibonacci(int n)
{
    if (n < 0) throw new System.ArgumentOutOfRangeException(nameof(n));
    System.Numerics.BigInteger a = 0, b = 1;
    for (int i = 0; i < n; i++)
    {
        var next = a + b;
        a = b;
        b = next;
    }
    return a;
}
```

迭代需要 O(n) 次加法、固定数量的大整数变量，但大整数的位数随 n 增长，不能把位复杂度也当作 O(n) 时间／O(1) 空间。快速倍增可以减少递推层数。

### 7. 如何实现“相同颜色四连通，达到三格就消除”？

**答案：**

先明确规则：这是**连通块消除**，不是只匹配连续横线／竖线的传统三消。原材料在递归返回时恢复格子，又没有正确使用 visited 阻止重复访问，容易重复计数。

下面约定 `None` 是空格；0 可以是合法颜色。一次扫描先找出所有符合条件的连通块，随后统一清除，不在搜索中回溯恢复已访问状态。

```python
def clear_components(board, min_size=3):
    if min_size < 1:
        raise ValueError("min_size must be positive")
    if not board:
        return 0
    rows, cols = len(board), len(board[0])
    if any(len(row) != cols for row in board):
        raise ValueError("board must be rectangular")
    visited, doomed = set(), set()
    for r in range(rows):
        for c in range(cols):
            if board[r][c] is None or (r, c) in visited:
                continue
            color = board[r][c]
            stack, group = [(r, c)], []
            visited.add((r, c))
            while stack:
                x, y = stack.pop()
                group.append((x, y))
                for nx, ny in ((x-1,y), (x+1,y), (x,y-1), (x,y+1)):
                    if (0 <= nx < rows and 0 <= ny < cols
                            and (nx, ny) not in visited
                            and board[nx][ny] == color):
                        visited.add((nx, ny))
                        stack.append((nx, ny))
            if len(group) >= min_size:
                doomed.update(group)
    for r, c in doomed:
        board[r][c] = None
    return len(doomed)
```

时间和辅助空间均为 O(行数 × 列数)。如果规则含下落、补充和连锁，应在这一轮完成后分阶段执行，再重新检测。

### 8. 传统三消与连通块消除有什么区别？

**答案：**

传统三消通常检查横向／纵向连续同色段，长度达到阈值后做标记，再一次性清除。L 形三个同色格可能是一个三格连通块，却没有任何连续三格直线，因此不能用同一个连通块算法直接替代。

推荐流程：扫描行列形成待消除集合 → 统一清除并计分 → 下落 → 补充 → 下一轮检测。交叉位置只计一次；特殊棋子、交换有效性与随机补充规则另行定义。

### 9. 如何手写 strcpy？为什么返回目标首地址？

**答案：**

下面保留经典 C 接口的调用契约：指针有效、源以空字符结尾、目标容量足够且两段内存不重叠。原签名没有容量参数，函数无法自行保证目标空间足够。

```c
char *copy_string(char *dest, const char *src)
{
    char *begin = dest;
    while ((*dest++ = *src++) != '\0')
    {
    }
    return begin;
}
```

返回首地址便于调用者继续使用目标字符串或组合表达式，而不是返回已经移动到末尾的指针。工程接口可显式接收容量并返回状态；重叠复制需另外设计，不可直接套用这个循环。

## 四、数据结构与算法补充

### 10. 链表题为什么常用哨兵节点和快慢指针？

**答案：**

哨兵把头部插删统一成“修改前驱 next”，减少空表／换头分支。反转链表要先保存 next，再改链接，最后推进 prev 和 current；时间 O(n)、额外空间 O(1)。

判环时 slow 每次一步、fast 两步，访问前检查 fast 及其 next；相遇后令一指针回到头部，两者都走一步，再相遇处为环入口。找倒数第 k 个可先拉开 k 步间距，但需处理 k≤0、长度不足与空链表。合并两个有序链表用双指针，说明是否复用原节点及谁负责释放。

### 11. 栈、队列、单调栈和单调队列各解决什么？

**答案：**

| 结构／模式 | 常见任务 | 核心不变量 |
| --- | --- | --- |
| 栈 | 括号匹配、撤销、DFS | 后进先出 |
| 队列 | BFS、消息处理 | 先进先出 |
| 双栈队列 | 用栈实现 FIFO | 出栈为空才整体倒入；操作摊还 O(1) |
| 单调栈 | 下一个更大元素、柱状图 | 维护未解决元素的单调候选 |
| 单调 deque | 滑动窗口极值 | 队首未过期、候选值保持单调 |

单调结构中每个索引通常最多进出一次，整体 O(n)，但不是每一次操作都只弹一个元素。循环队列可用独立 size，或预留一个槽区分空满；头尾指针相等本身不能同时区分两者。

### 12. 二叉树遍历、完全性与 LCA 应检查哪些条件？

**答案：**

前／中／后序分别在左右递归之前、中间、之后访问根；层序用队列，按入队前的本层大小分层。迭代中序维护“当前节点的未访问左链”，不要把所有节点一次入栈后误以为已有序。

完全二叉树最后一层从左到右连续；层序遇到首个缺失孩子后，不应再出现后续非空节点。BST 是全子树键序约束，不只是根比直接孩子大／小；校验可递归传边界或检查中序序列。

普通二叉树的 LCA 可递归寻找两侧：各一目标则当前点为答案，单侧找到则向上返回。经典短写法假设两个目标都存在，若输入不保证，须同时统计找到的目标。遍历 O(n)，递归栈 O(h)，极深树考虑显式栈。

### 13. 平衡搜索树与哈希表的关键取舍是什么？

**答案：**

普通 BST 最坏可退化为链。AVL 用更严格的高度平衡，红黑树用颜色和黑高约束维持对数高度；理解为何旋转保持中序顺序，比背各删除分支的旋转次数更重要。

哈希表依赖哈希质量、冲突处理和负载，平均查询 O(1)，最坏 O(n)。链地址法与开放寻址各有局部性和删除代价；开放寻址可用墓碑或满足条件的后移删除，不能简单清空探测链中间位置。桶数不必须是质数，二次幂容量也可搭配合适哈希和寻址规则。

有序范围查询选平衡树等有序结构，单点查询考虑哈希；STL 对照见 [C++ 专题](C++高频题整理.md)第 63 题。

### 14. TopK 为什么常用堆？何时改用快速选择？

**答案：**

前 k 大可维护 k 大小的小顶堆：未满则插入，满后只有比堆顶大的候选才替换；时间 O(n log k)、空间 O(k)，适合流式输入。返回有序结果还需处理最后的堆内排序。

内存内可修改数组时，Quickselect 平均 O(n)，常见实现最坏 O(n²)；迭代版本可避免递归栈，`nth_element` 是相应 STL 入口。若需要前 k 项已经排好，可用 partial_sort。先约定 k=0、k>n、重复值和是否保留输入。

堆的自底向上建堆为 O(n)，并非把每个节点都按 O(log n) 简单相乘；多数节点离叶子很近。

### 15. LRU Cache 怎样同时实现快速查找和淘汰？

**答案：**

哈希表保存 key→链表节点，双向链表保存最近使用顺序。命中后把节点移到表头，新增也插表头；超容量时从表尾淘汰，并同步删除哈希索引。平均 get／put O(1)，空间 O(capacity)。

处理容量为 0、已存在 key 更新、失效迭代器和线程同步。若用 `std::list::splice`，节点移动可避免重新分配；链表和索引要始终一致。LRU 只基于最近使用，顺序扫描可能挤掉热点，实际缓存还可考虑大小、加载成本与不同淘汰策略。

### 16. SparseSet、Bitmap 与 Bloom Filter 分别适合什么？

**答案：**

SparseSet 用 dense 连续存活 ID、sparse 保存反向位置；查询检查 `x` 范围、位置范围及 `dense[sparse[x]]==x`。删除用尾元素覆盖并修正其反向索引，O(1) 但不保持顺序；新增受容量扩张影响通常摊还 O(1)。ID 范围很大时可分页，实体复用还需 generation 防止旧句柄命中。

Bitmap 对有界整数域按位记录，n 位约占 `ceil(n/8)` 字节；同一字中的并发位写需要同步。Bloom Filter 以多重哈希置位，正常插入且未错误删除的条件下可有假阳性、无假阴性；普通版本不能直接清某 key 的共享位，需计数等扩展支持删除。

### 17. 并查集、Trie 与跳表的基本用途是什么？

**答案：**

- 并查集维护集合归属，路径压缩＋按秩／大小合并使一系列操作摊还接近常数，更精确为逆 Ackermann 量级；适合连通性，不直接解决一般动态删边。
- Trie 以字符／符号前缀共享路径，适合前缀匹配；O(字符串长度) 查询还取决于子节点访问方式，空间与字符集有关。
- 跳表用多层索引链表加速有序搜索，典型随机设计期望 O(log n)，最坏可 O(n)；并发友好需要专门的同步和内存回收设计。

掌握问题适配和复杂度即可，具体旋转、随机层数常数或产品内部版本实现不作为通用结论。

### 18. 贪心、回溯、DP、分治与滑动窗口如何选？

**答案：**

| 思路 | 判断依据 | 常见误区 |
| --- | --- | --- |
| 贪心 | 可证明局部决策不损失全局最优 | 几个例子成立就当证明 |
| 回溯 | 枚举选择并撤销分支状态 | 把所有 DFS 的 visited 都撤销，造成重复遍历 |
| DP | 状态概括后续所需信息，复用子结果 | 状态遗漏历史，或转移／遍历顺序不匹配 |
| 分治 | 拆解后有清晰的合并过程 | 漏掉跨分界答案 |
| 滑动窗口 | 连续区间且维护／收缩规则能单调推进 | 任意含负数的区间和问题都强行双指针 |

先说清状态和不变量，再写步骤。0–1 背包一维倒序是为了不在同轮复用当前物品；完全背包常用正序。不存在“拿不准一律 DP”或“n≤20 一律回溯”的可靠规则。

### 19. 拓扑排序、判环与最短路怎样区分？

**答案：**

邻接表空间 O(V+E)，适合稀疏图；邻接矩阵空间 O(V²)，判边直接。拓扑排序处理有向依赖：Kahn 算法从零入度队列出发，逐边减入度；处理节点数小于 V 表示有环。空图合法地返回空序列，不能把所有空结果都判成失败。

有向图 DFS 可用未访问／在路径中／已完成三色判环；无向图需排除父边，多重边时用边 ID 避免错误。

无权最短路用 BFS；非负权用 Dijkstra，优先队列版需跳过旧距离条目；含负权时不能直接沿用其贪心确定性。Bellman–Ford 可处理负边并检测相关负环，Floyd–Warshall 用于适合规模的全点对。距离累加需防溢出；网格有钥匙等条件时，visited 应包含位置之外的状态。
